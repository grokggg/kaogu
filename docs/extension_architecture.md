# 非侵入式扩展架构设计文档

## 一、架构概述

本项目采用**非侵入式扩展架构**+**动态加载机制**，通用模板引擎作为独立模块接入，不修改原系统核心代码，不破坏原有工作流。

```
用户输入
    │
    ▼
┌─────────────────────────────────────────┐
│           main.py 入口层                 │
│  ┌─────────────────────────────────┐    │
│  │  try/except 安全导入扩展模块     │    │
│  │  扩展加载失败 → 原系统正常运行    │    │
│  └─────────────────────────────────┘    │
│              │                          │
│     ┌────────┴────────┐                 │
│     ▼                 ▼                 │
│  标准模式          增强模式（可选）       │
│  (默认)            (--enable-universal) │
│     │                 │                 │
│     │           ┌─────┴──────┐          │
│     │           ▼            ▼          │
│     │    UniversalPrompt  Conflict-     │
│     │    (通用模板引擎)    Detector     │
│     │                      (冲突检测)   │
│     │           │            │          │
│     └─────┬─────┴─────┬──────┘          │
│           ▼           ▼                 │
│     原系统提示词  附加增强层              │
│     (未修改)    (动态加载，沙盒附加)      │
│           │           │                 │
│           └─────┬─────┘                 │
│                 ▼                       │
│        生成任务文件（独立沙盒）           │
└─────────────────────────────────────────┘
    │
    ▼
Trae 执行研究 → 输出报告 → 自动校验 → 审计日志
```

## 二、核心设计原则

### 1. 绝对禁止事项
- ❌ 不得直接改写原智能体的 `system_prompt.md` 文件
- ❌ 不得修改原有类的核心方法签名和核心逻辑
- ❌ 禁止共享同一数据库连接池（扩展使用独立的audit目录）
- ❌ 扩展模块导入失败必须静默降级，不得导致原系统崩溃
- ❌ 不得在增强层覆盖原系统提示词，只能附加补充规则

### 2. 推荐实践
- ✅ 使用 try/except 安全导入扩展模块
- ✅ 通过命令行参数 `--enable-universal` 显式启用增强模式
- ✅ 增强层作为独立章节附加在任务文件末尾，不插入原提示词中间
- ✅ 审计日志独立存储在 `outputs/audit/` 目录
- ✅ 朝代参数库使用YAML配置，新增朝代只需修改配置文件
- ✅ 冲突检测器内置否定语境识别，避免误报正确的"禁止使用"说明

## 四、双轨运行机制

### 标准模式（默认，无侵入）
```bash
python main.py --dynasty "西汉" --period "武帝时期" --object "服饰"
```
- 扩展模块完全不加载
- 行为与接入扩展前完全一致
- 无任何性能损耗

### 增强模式（显式启用）
```bash
python main.py --dynasty "西汉" --period "武帝时期" --object "服饰" --enable-universal
```
- 安全加载扩展模块（失败则自动降级到标准模式）
- 在任务文件中附加【通用模板引擎增强层】独立章节
- 包含：6条底层铁则 + 动态加载的朝代专属参数 + 校验要求
- 不覆盖原系统提示词，仅作为补充规则

### 双轨输出协同

| 维度 | 原版智能体 | 通用模板引擎 | 协同方式 |
|------|-----------|-------------|---------|
| 知识库 | 固定提示词规则集 | 动态朝代参数库（YAML配置） | 增强层附加，不替换 |
| 输出格式 | Markdown标准10章节 | Markdown附加校验章节 | 合并在同一任务文件 |
| 错误处理 | 原系统规则 | 冲突检测器自动校验 | 校验分数<85标记需人工复核 |
| 存储 | outputs/tasks/ | outputs/audit/独立目录 | 不共享存储 |
| 部署 | 原流程 | 新增模块文件 | 无需容器，直接文件拷贝 |

## 五、冲突检测机制

### 检测等级
| 等级 | 颜色 | 扣分 | 处理方式 |
|------|------|------|---------|
| CRITICAL（致命） | 原则性跨时代错误 | -50/项 | 标记is_valid=False，禁止输出 |
| HIGH（严重） | 明显史实错误 | -20/项 | 标记需修正 |
| MEDIUM（中度） | 数据偏差 | -10/项 | 标注警告 |
| LOW（轻度） | 细节问题 | -3/项 | 提示 |

### 当前支持的检测项
1. **跨时代元素混入检测**：各朝代禁止出现的建筑/服饰/器物（如西汉出现琉璃瓦/椅子/补子/青花瓷/马蹄袖等）
2. **度量衡数据校验**：如汉尺必须在22.5-24.0cm范围内
3. **禁用来源检测**：禁止引用百度百科/影视剧/游戏/AI生成内容
4. **否定语境智能识别**：正确识别"禁止使用琉璃瓦"这类正确的否定说明，不误报

### 可检测的典型错误（已测试验证）
```
输入："西汉长安城使用琉璃瓦屋顶，城墙包砖，官员头戴乌纱帽，
       身穿补子官服，坐在椅子上，使用青花瓷餐具。汉尺约30厘米。"

检测结果：
- [CRITICAL] 补子（补子制度始于明代）
- [CRITICAL] 青花瓷（青花瓷成熟于元代）
- [HIGH] 琉璃瓦（北魏始有）
- [HIGH] 城墙包砖（明代大规模普及）
- [HIGH] 乌纱帽（东晋起源，隋唐定名）
- [HIGH] 椅子（东汉以后传入）
- [MEDIUM] 汉尺30cm（应为23.1cm）
最终分数：0/100，需人工复核
```

## 六、朝代参数库扩展

### 已内置朝代
- 西汉（含张骞出使时期特别说明：桂宫/明光宫/建章宫未建成标注）
- 东汉
- 唐（含长安城精确尺寸、舆服制度、建筑规范）
- 北宋（含《营造法式》、虹桥构造、里坊制崩溃）
- 明（含补子制度、砖包城墙、琉璃等级）
- 清（含工程做法则例、剃发易服、顶戴花翎）

### 新增朝代方法
只需在 `config/era_configs.yaml` 中添加对应朝代的配置节点，无需修改Python代码：

```yaml
新朝代名:
  度量衡锚点:
    1尺: "XX厘米"
  建筑规范:
    ...
  服饰禁忌:
    ...
  地图精度:
    ...
```

同时在 `tools/conflict_detector.py` 的 `forbidden_patterns` 字典中添加该朝代的禁止元素正则表达式。

## 七、使用示例

### 测试通用模板引擎独立运行
```bash
cd chinese-material-culture-agent
python tools/universal_template.py --dynasty "西汉" --object "建筑"
```

### 测试冲突检测器
```bash
python -c "
from tools.conflict_detector import ConflictDetector
detector = ConflictDetector()
result = detector.validate_output('你的复原文本', '西汉')
print(f'分数: {result.score}/100')
for c in result.conflicts:
    print(f'  [{c.severity.value}] {c.description}')
"
```

### 生成增强模式研究任务
```bash
python main.py \
  --dynasty "西汉" \
  --period "武帝时期" \
  --object "贵族女性服饰" \
  --identity "贵族女性" \
  --scene "日常起居" \
  --enable-universal
```

## 八、内存与性能保障

- 标准模式：零额外开销，与接入前完全相同
- 增强模式：扩展模块加载约增加0.1秒启动时间，任务文件大小增加约2-4KB（增强层内容）
- 内存：扩展模块独立实例，不与原系统共享状态，内存占用增量<5MB
- 审计日志：每次任务生成一个独立JSON文件，平均<2KB
